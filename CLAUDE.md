# Project Guidelines

## Explanations
- When asked to explain code, keep answers short and precise.

## Coding
- Follow standard Go best practices (idiomatic naming, error handling, `gofmt`, small packages).
- Use Interface First Design: define the interface before the implementation, and depend on interfaces, not concrete types.

## Testing
- Add or update tests for every feature or code change.
- Use the Test Suite Pattern (e.g. `testify/suite`) for tests.

## Documentation
- Update `README.md` whenever a change affects behavior, setup, APIs, or usage.
